📝 ショート動画v11→v15一気更新の裏側

今日やったこと（ざっくり）

AIショートアニメを自動生成するツールを、まる一日かけて大改修しました。テンプレ（ショート）のバージョンをv11→v13→v15と段階的に積み上げ、UIも5フェーズに分けて整理。バグ修正・高速化・共通化・読み取り専用化まで一気に進めた『総点検デー』です。

ルピナス （ふつう）
今日は朝から晩までAIショート動画の制作ツールを大改修してたの。
アイリス （びっくり）
えっ、なんでそんな一気に？壊れたの！？
ルピナス （呆れ）
ep077から085まで連続で作ってたら、気になるとこが山積みになっちゃって…まとめて直したほうが早いって判断したの。
フィオナ （考え中）
いわゆる『観察してから直す』ですね。たくさん回して傾向が見えてから手を入れる方が、闇雲に直すより効率的です。

学び①：すぐ直さず、たくさん作ってから直す

動画を10本くらい連続生成すると、『毎回ここが気になる』『この演出だけ浮く』というパターンが見えてきます。1本ごとに直すと“その場しのぎ”になりがちですが、まとめて観察してから直すと根本原因にたどり着きやすい。AIものづくりでは『直す前に観察する時間』をちゃんと取るのが大事です。

アイリス （笑顔）
なるほどー！じゃあ最初は雑に作っていいんだ！
ルピナス （ウインク）
雑というか、“仮で量を出す”ね。質は後でまとめて上げる。

今日触ったところ

1. ショートテンプレを v11 / v13 / v15 と段階更新

  • v11：新規追加。立ち絵の顔位置（face_target_y）を修正。
  • v13：OPにレターボックス（上下黒帯）を導入して“映画っぽさ”を演出。BGM切替の挙動も強化。
  • v15：機能拡張＋タイトルコールに改行を入れて読みやすく。ショートの立ち絵配置も微調整。

2. UI を 5 フェーズに分けて整理

Phase やったこと
1 緊急バグ修正：API経由とサブスク経路を統一、script_only の伝達修正
2 （古い実装の）削除
3+4 テーマ生成を共有モジュール化／設定タブを read-only に
5 rerun の間隔を調整して高速化
フィオナ （ふつう）
いきなり全部直すのではなく、フェーズに分けたのが今日のポイントです。
アイリス （考え中）
フェーズに分けるって、なにがいいの？一気にやればいいじゃん？
ルピナス （大笑い）
アイリス、それで前に全部壊したでしょ？
アイリス （あわあわ）
うっ…そういえば…

学び②：改修は『フェーズ分け』で

大きな変更を一気に入れると、どこで壊れたか分からなくなるのが一番の事故。今日は意識して順番をつけました。

  1. まず止血（Phase 1：致命バグだけ最優先で直す）
  2. 要らないものを消す（Phase 2：削除）
  3. 重複を共通化（Phase 3+4：同じ処理をひとつにまとめる）
  4. 最後に高速化（Phase 5：速度チューニング）

この順番がポイントで、最初に速度を上げると壊れていることに気づきにくいので、必ず『直す→整える→速くする』の順にします。

フィオナ （笑顔）
順番を守るだけで、事故の確率がぐっと下がります。

学び③：『共有モジュール化』で同じバグを二度と踏まない

テーマ生成のロジックを、複数の場所で別々に書いていたのを ひとつの共有モジュールにまとめました。

  • 以前は『API経由』と『サブスク経路』で似たコードが二重に存在 → 片方だけ直して片方を忘れる事故が頻発
  • 今日は両者を統一して、修正は1か所で済むように

AIでものづくりしていると、ついコピペで“似たもの”が増えがち。『同じことを2回書いたら共通化のサイン』 と覚えておくと、後で楽になります。

アイリス （ドヤ顔）
コピペ最高！って思ってたけど、後で困るのか…
ルピナス （ふつう）
そう。コピペは“今のラク”、共通化は“未来のラク”ね。

学び④：設定タブを『read-only』にする意味

設定タブをあえて『見るだけ・編集不可』にしました。

  • 編集できると、つい本番中に触ってしまって事故る
  • 『どこで設定が決まっているか』を一本化したい

“触れないようにする”ことで安全性を上げる という、地味だけど効く工夫です。

フィオナ （ふつう）
自由度を下げるのも、立派な設計判断なんですよ。

学び⑤：演出の『不変ルール（unchangeable_facts）』を検証

v13では、シナリオ生成時に 『絶対に変えてはいけない設定』 がちゃんと守られているか検証する仕組みを強化しました。

  • 例：キャラの一人称、髪の色、関係性
  • AIに任せると、回によって微妙に揺れる → 視聴者が違和感を覚える
  • 『不変ルール』を明示してチェックすることで、シリーズとしての一貫性 が保てます

AIキャラを継続運用するなら、この“ぶれない芯”を仕組みで守るのが必須です。

アイリス （衝撃）
ええっ、あたしの一人称が『私』になってた回あったの！？
ルピナス （泣き）
あったの。だから今日それを直したの…
フィオナ （照れ）
気づかれていなくて良かったです…

学び⑥：『高速化は最後』のもうひとつの理由

Phase 5で UI の rerun 間隔を調整して高速化しました。

  • rerun = 画面を作り直す回数。頻繁にやると重くなる
  • 必要なときだけ作り直すよう間隔を空けた

ただしこれは すべての修正が終わった後にやる作業。途中でやると『速くなったけど挙動が変』という最悪パターンを引きます。

ルピナス （ふつう）
今日の配信は無し。ツール改修に集中の一日でした。
アイリス （笑顔）
次の配信スケジュールはXをチェックしてね！

※ 最新の配信情報は X（https://x.com/irisfionaAIBS） を参照してください。

まとめ：今日の有意義ポイント

  • 観察してから直す：1本ごとに直さず、複数本作って傾向を掴んでから修正する
  • 改修はフェーズ分け：止血 → 削除 → 共通化 → 高速化、の順を守る
  • 『同じことを2回書いたら共通化のサイン』：API経路の二重実装を一本化
  • 触れないことで安全性を上げる：設定タブを read-only に
  • 不変ルールを仕組みで守る：キャラの一貫性は『AI任せ』にせず検証する
  • 高速化は最後にやる：先にやると壊れに気づけない
  • 演出の小ワザ：OPのレターボックスやタイトルコールの改行で“映画感”と読みやすさは両立できる
