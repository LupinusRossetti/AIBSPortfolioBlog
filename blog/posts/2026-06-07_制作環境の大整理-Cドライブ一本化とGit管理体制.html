① Cドライブ一本化への方針転換

今日の最大のテーマがこれ。これまで創作物や仕掛かり中のプロジェクトは G:\マイドライブ\ClaudeCode\ に置いていました。Googleドライブで自動同期されるので、「もし端末が壊れてもクラウドに残るから安心」という発想だったんです。

ただ、運用してみてだんだん不安が出てきました。

  • 同期が遅れることがある（保存したのに反映されない）
  • 同期中にアプリが書き込むとファイルが壊れることがある
  • ネット状況によってはロックがかかって編集できない

「クラウドに置いておけば安心」のつもりが、創作の足を引っ張る原因になっていたんです。

そこで方針を変えました。

正本（オリジナル）は Cドライブ C:\ClaudeCode\ に置く。Gドライブはあくまでそのコピー。

フィオナ （考え中）
「原本」と「コピー」を分けるのは大事ですね。机の上で書いている下書き（C）と、念のための写し（G）。同じものに見えても役割が違います。
ルピナス （ふつう）
そうなの。正本がクラウド同期のフォルダにあると、書きかけのものまで毎回送られるから、衝突や壊れ事故が起きやすいのよね。
アイリス （びっくり）

再現のコツ：作業場と保管場所を分ける

  • 作業中のファイルはクラウド同期されない「ローカル」（C）に置く
  • 完成品やバックアップは同期フォルダ（G）にコピーで残す
  • 「全部クラウド」も「全部ローカル」もリスクがある。両立させる

Gitで管理しておくと、いつ・どこを・どう変えたかが全部残ります。間違って消してしまっても、「昨日の状態に戻す」が一瞬でできるんですよ。

Gitって何がうれしいの？（やさしい例え）

  • ファイルの写真を時々撮っておくと、いつでもその瞬間に戻せる ← これがGitの「コミット」
  • 「一行間違えて消した！」を昨日の写真から復元できる
  • 「誰が・いつ・なぜ・何を変えたか」がメモ付きで残る

要するに、創作物が消えない・元に戻せる・経緯がわかる——この3つの安心がいっぺんに手に入ります。

③ .gitignore で「リポに入れちゃダメなもの」を仕分け

3つ目は地味だけど超大事。Git管理を始めるときに、「履歴に残してはいけないファイル」をちゃんと除外しておく作業です。

リポジトリは「みんなで共有する書類棚」みたいなものなので、入れたらマズいものを最初にはじき出しておきます。

共通で除外したもの

  • __pycache__/ … Pythonが内部で作る一時ファイル（残しても意味がない）
  • .env … APIキーなどの秘密情報を書き込むファイル（絶対に流出させない）
  • Thumbs.db … Windowsが勝手に作るサムネキャッシュ

flow-*系のリポでさらに除外したもの

  • output/ … 動画の書き出し先（1ファイルで数百MBになることもある）

動画ファイルや画像の書き出し結果は、Gitで履歴管理してもうれしくありません（巨大すぎてリポが重くなる・更新のたびに全部コピーされる）。「作り方の手順（コード）」だけリポに残し、「出来上がった成果物」は別管理——この線引きが大切です。

ルピナス （衝撃）

フィオナ （ふつう）

再現のコツ：仕分けの3原則

  • 生成物（出力）は除外：手順だけ残す
  • 一時ファイルは除外：履歴の役に立たない
  • 秘密情報は絶対に除外：別の金庫（パスワードマネージャー）で管理する

④ これからの運用

最後に、今日整えた仕組みをどう使っていくかのお話。

  • 大事なものはGitに記録 → 消えない・履歴が残る
  • Cドライブ＝正本で動かして、Gドライブ＝自動同期される写しとして使う
  • 端末が壊れたときの保険として、将来はGitHubのプライベートリポジトリにも push しておく（クラウドにもう一段のバックアップを置く）

「派手な機能を作る日」と「土台を整える日」は両方必要で、土台がしっかりしていると、派手な作業のときに事故が減ります。今日はその土台のお手入れができた一日でした。

まとめ：今日の有意義ポイント

  • クラウド同期フォルダを「正本」にしない：同期遅延・衝突・破損のリスクがあるので、作業中のファイルはローカル（C）に置き、同期フォルダ（G）は写しに使う。
  • プロジェクトは小さく分けて、それぞれGit管理：13個のリポをまとめて git init。プロジェクトごとに「日記帳」を持たせると、消えない・戻せる・経緯がわかる、の三拍子。
  • .gitignore で“入れちゃダメ”を最初に決める：一時ファイル（__pycache__/ 等）、秘密情報（.env）、巨大な生成物（output/）は履歴に入れない。コード（手順）と成果物（結果）を切り分ける。
  • 秘密情報は別の金庫で：パスワードや鍵はリポではなくパスワードマネージャーで管理。リポにはアカウント名や使い方のメモだけ。
  • 派手な制作と土台整備は両輪：土台が崩れると派手な作業が事故る。地味な整理整頓こそ、長く続けるための一番の投資。
